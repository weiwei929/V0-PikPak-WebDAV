# PikPak WebDAV 视频播放器

## 项目简介
PikPak WebDAV 视频播放器是一个基于Flask的Web应用程序，专为PikPak网盘设计的视频播放解决方案，同时也适用于任何支持WebDAV协议的网络存储服务。该项目特别解决了WebDAV访问中文件路径包含特殊字符和中文时的编码问题。

## 核心功能

### ID导航系统
- **路径映射**: 将复杂的WebDAV路径映射为简单的数字ID
- **永久链接**: 即使文件名包含特殊字符或中文，也能稳定访问
- **持久化存储**: 重启服务器后保留ID映射关系

### 媒体功能
- **视频流**: 支持大型视频文件的流式传输
- **断点续传**: 实现HTTP Range请求，支持视频拖拽播放
- **播放列表**: 自动生成当前目录及子目录的视频播放列表
- **媒体信息**: 显示视频文件大小、类型、修改日期等信息

### 用户界面
- **响应式设计**: 适配桌面和移动设备
- **多种视图**: 支持列表视图和网格视图
- **黑暗模式**: 内置暗色主题支持
- **文件搜索**: 支持按文件名搜索

## ID导航系统：解决WebDAV访问的核心挑战

### 问题背景

在开发过程中，我们遇到了WebDAV访问中的一个根本性挑战：**复杂路径的编码问题**。当文件路径包含中文、特殊字符或复杂Unicode字符时，不同的WebDAV客户端、服务器和浏览器会使用不同的URL编码方式，导致以下问题：

1. **不一致的路径表示**：同一个文件路径在不同系统中可能有多种URL编码形式
2. **编码转换失败**：在HTTP请求传递过程中，路径可能多次被编码或解码，造成字符损坏
3. **特殊字符处理**：某些特殊字符（如`#`、`?`、`%`）在URL中有特殊含义，需要额外编码处理
4. **长路径问题**：多层嵌套目录的中文路径经过编码后可能超出URL长度限制

### 解决方案探索历程

#### 第一阶段：传统路径处理

最初，我们尝试通过标准的URL编码/解码函数处理路径：

- 使用`urllib.parse.quote`和`urllib.parse.unquote`函数
- 尝试不同的编码方式（UTF-8、GBK等）
- 实现多重编码检测和修复

这种方法在简单场景下有效，但在复杂路径（尤其是包含多种语言字符的路径）下仍然失败。我们发现一个关键问题：**无法预测WebDAV服务器的具体编码行为**。

#### 第二阶段：缓存和模式匹配

之后，我们尝试建立缓存系统：

- 保存成功匹配的路径模式
- 使用路径模糊匹配算法
- 实现自动修复机制

这提高了成功率，但仍有边缘情况无法解决，特别是在多种编码混用的情况下。

#### 第三阶段：借鉴PotPlayer的ID导航思想

突破性的灵感来自对PotPlayer WebDAV实现的分析。我们发现PotPlayer不直接处理复杂路径，而是采用ID映射系统：

- 每个路径被分配一个简单的数字ID
- 导航和访问完全基于ID而非原始路径
- 后端维护ID到路径的映射关系

这种方法从根本上规避了路径编码问题。

### ID导航系统实现原理

#### 核心概念

1. **路径到ID的单向映射**：每个目录和文件被分配一个唯一ID
   - 目录ID格式：`dir_X`（如`dir_1`、`dir_2`）
   - 文件ID格式：`file_X`（如`file_1`、`file_2`）

2. **持久化映射存储**：
   - 映射关系序列化保存到本地文件系统
   - 应用重启后自动恢复映射关系
   - 增量保存机制，避免频繁I/O操作

3. **请求流程转换**：
   - 用户浏览：显示ID而非实际路径
   - 用户请求：通过ID访问文件
   - 后端转换：将ID解析为原始路径，进行WebDAV操作
   - 响应处理：返回结果中使用ID代替路径

#### 技术优势

1. **完全规避编码问题**：因为暴露给用户的始终是简单的ID字符串，不再需要担心复杂路径编码
2. **更高的性能**：简单ID的处理比复杂路径匹配效率更高
3. **更好的兼容性**：可适用于任何WebDAV服务器，无需针对不同服务器定制编码处理逻辑
4. **更稳定的链接**：即使原始路径包含特殊字符，基于ID的链接也不会失效

#### 实现细节

- **惰性初始化**：首次访问路径时才生成并分配ID
- **智能节流**：每20个新ID或每分钟最多保存一次，避免过度I/O
- **优雅降级**：保留对传统路径格式的支持，确保向后兼容
- **错误恢复**：完善的错误处理和日志记录，便于调试和维护

### 与其他解决方案的比较

| 解决方案 | 优点 | 缺点 |
|---------|-----|------|
| 标准URL编码 | 实现简单，标准化 | 不同系统实现不一致，多重编码问题 |
| 多种编码尝试 | 提高成功率 | 性能开销大，无法覆盖所有情况 |
| 路径缓存 | 提高重复访问性能 | 无法解决首次访问问题 |
| **ID导航系统** | 彻底避开路径编码问题，高性能，高可靠性 | 需要维护额外的映射关系 |

通过ID导航系统，我们成功解决了WebDAV访问中最棘手的问题，让视频播放体验更加流畅可靠。

## 系统要求
- Python 3.6+
- Flask & Flask-CORS
- Requests
- lxml

## 安装指南

### 1. 克隆仓库
```bash
git clone https://github.com/weiwei929/V0-PikPak-WebDAV.git
cd V0-PikPak-WebDAV
```

### 2. 安装依赖
```bash
pip install flask flask-cors requests lxml
```

### 3. 启动应用
```bash
python app.py
```

### 4. 访问应用
在浏览器中打开 `http://localhost:5000`

## 使用方法

### 连接WebDAV服务
1. 在首页输入WebDAV服务器URL
2. 输入用户名和密码
3. 点击"连接"按钮

### 浏览和播放
1. 通过文件浏览器导航到包含视频的文件夹
2. 点击视频文件开始播放
3. 使用播放控件调整播放进度、音量等

### 播放列表功能
1. 进入包含视频的文件夹
2. 点击"创建播放列表"按钮
3. 使用播放列表控件切换视频
